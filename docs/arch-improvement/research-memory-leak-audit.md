## 2. Анализ первопричин зависания браузера (Root Causes)

В ходе детального исследования кодовой базы `src/` выявлено **5 критических источников утечек памяти и деградации производительности**:

### Причина 1: Экстремальный GC Thrashing в Canvas 2D (2,580 аллокаций градиентов в секунду)
- **Файлы:** `src/canvas/hearth-flame.ts:133-149`, `src/canvas/hearth-particles.ts:81-125`
- **Код:**
  В цикле анимации `requestAnimationFrame` (60–120 FPS):
  - 8 языков пламени создают `ctx.createLinearGradient()` + 4 `addColorStop` на каждом кадре.
  - 10 микро-вспышек (licks) создают `ctx.createRadialGradient()` + 3 `addColorStop` на каждом кадре.
  - 24 тепловых вихря (puffs) создают `ctx.createRadialGradient()` + 3 `addColorStop` на каждом кадре.
  - 1 световой ореол пола создает `ctx.createRadialGradient()`.
- **Измерение (Benchmark):**
  - За 10 секунд работы (600 кадров) генерируется **25 800 объектов `CanvasGradient`** (~5.6 МБ сырого мусора).
  - За 1 минуту: **154 800 объектов**.
  - За 10 минут: **более 1.5 миллионов объектов `CanvasGradient`**!
- **Следствие:** Градиент в Chromium/WebKit — это нативный C++ объект движка Skia/Blink, обернутый в V8. При такой частоте создания сборщик мусора V8 (Scavenger) захлебывается, инициирует длительные «stop-the-world» Full GC паузы (100–500 мс), что приводит к заиканию, нарастанию лага и полной блокировке интерфейсного потока браузера.

---

### Причина 2: Утечка узлов Web Audio Graph (Leaking Un-disconnected AudioNodes)
- **Файл:** `src/audio/audio-engine.ts:80-145, 175-215`
- **Код:**
  ```typescript
  // playTone:
  const o1 = this.ac.createOscillator();
  const o2 = this.ac.createOscillator();
  const lp = this.ac.createBiquadFilter();
  const g = this.ac.createGain();
  o1.connect(lp); o2.connect(...); lp.connect(g); g.connect(this.voiceBus);
  o1.stop(end); o2.stop(end);
  // НЕТ o1.disconnect(), g.disconnect()!
  ```
- **Спецификация W3C Web Audio API:**
  Метод `node.stop()` прекращает генерацию звука, но **НЕ отключает узел от графа**. Узлы, подключенные к активной шине `voiceBus` $\to$ `master` $\to$ `destination`, продолжают удерживаться в графе движка и обрабатываться аудиопотоком каждые 128 сэмплов (2.9 мс).
- **Следствие:**
  Каждая реплика в салон создает 10 узлов (`playTone` вызывается дважды). В демо-режиме (каждые 5.5 сек) за 15 минут накапливается **более 1 600 активных AudioNode**, что перегружает вещественный DSP-тред Web Audio, вызывая треск звука и зависание вкладки. Аналогично в `captureMeetingAudio()` узел `MediaStreamAudioSourceNode` никогда не отключался от анализатора.

### Причина 3: Безлимитный массив слов и экспоненциальный `shadowBlur`
- **Файл:** `src/canvas/hearth-words.ts:114, 195-207`
- **Код:**
  Массив `this.words.push(item)` не имеет верхнего лимита (capacity cap). При длительной сессии накапливаются десятки и сотни слов.
  На каждом кадре для каждого слова вызывается:
  `ctx.shadowBlur = 8; ctx.fillText(label, 0, 0);`
- **Следствие:**
  `shadowBlur` в Canvas 2D — это операция двумерной фильтрации Гаусса. Отрисовка 50+ элементов с размытием теней на частоте 60 FPS обрушивает производительность GPU-композитора, взвинчивая время кадра с 1.2 мс до 45+ мс.

---

### Причина 4: Накопление инстансов `MediaRecorder` на непрерывном аудиопотоке
- **Файл:** `src/speech/stream-recorder.ts:130-155`
- **Код:**
  В `extractCurrentSegment()` каждые 4.5 секунды вызывается `this.mediaRecorder.stop()` и создается новый `new MediaRecorder(stream)` без обнуления слушателей (`ondataavailable = null`, `onstop = null`) у старого инстанса.
- **Следствие:**
  В браузерах на базе Chromium нативные обработчики медиа-кодека WebM Opus могут удерживать ссылки на внутренние пайплайны, приводя к скрытой утечке дескрипторов и памяти в процессе RenderProcess.

---

### Причина 5: Отсутствие таймаута на subprocess `ffmpeg` в сервисе биометрии
- **Файл:** `sherpa-speaker-service/src/audio-decoder.ts:12-40`
- **Код:**
  `const ff = spawn("ffmpeg", [...])` не имел таймаута принудительного завершения.
- **Следствие:**
  При передаче поврежденного или заблокированного аудиопотока процесс `ffmpeg` мог зависнуть в ожидании данных на `pipe:0`, оставаясь зомби-процессом в памяти ОС.

## 3. Архитектурный план оздоровления (Fix Plan)

1. **Кеширование и оптимизация градиентов (Canvas Gradient Pooling):**
   - Перевести статические радиальные градиенты (ореол поляны, частицы) на кешированные шаблоны или параметрические переиспользуемые градиенты вместо создания тысяч объектов в секунду.
2. **Гарантированный cleanup узлов Web Audio (AP-012, AP-023):**
   - Добавить слушатель `onended` на каждый создаваемый `OscillatorNode` с автоматическим каскадным вызовом `.disconnect()` для всех промежуточных `GainNode` и `BiquadFilterNode`.
   - В `disconnectMeetingAudio()` явно вызывать `this.meetingSource?.disconnect()` и `this.analyser?.disconnect()`.
3. **Ограничение емкости слов и оптимизация рендеринга (LRU Word Ring):**
   - Ввести жесткий лимит `maxWords = 36` в `HearthWordsManager`: самые старые остывшие слова плавно растворяются и удаляются из массива.
   - Включать `shadowBlur` строго только для последнего активного слова (`isLatest`), а для остывших слов использовать плоский контрастный цвет без тяжелого гауссова размытия.
4. **Очистка слушателей `MediaRecorder` в `StreamRecorder`:**
   - Перед пересозданием рекордера явно очищать ссылки `ondataavailable = null` и `onstop = null`.
5. **Таймаут безопасности на ffmpeg (Circuit Breaker):**
   - Добавить сторожевой таймер на 3000 мс с принудительным `ff.kill("SIGKILL")` при зависании.
