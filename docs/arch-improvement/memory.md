## 2026-10-22 - OpenAI Audio API Standard & Multi-ASR DI
- Context: Переход на мультивендорный ASR (GigaAM v3 + Whisper Large Turbo) и стандартизацию протоколов.
- Symptom: Разные ASR-серверы исторически имели разные кастомные эндпоинты (`/inference` у whisper.cpp, `/v1/transcribe` у некоторых Rust/Python шлюзов), что провоцировало спагетти-код в адаптерах.
- Cause: Отсутствие единого DTO/API контракта (AP-026) на уровне клиента.
- Use next time: Всегда использовать спецификацию OpenAI Audio API (`POST /v1/audio/transcriptions` с multipart/form-data) как базовый контракт. Любой новый ASR подключается как `SpeechToTextPort` через универсальный `OpenAiSpeechAdapter`.
- Evidence: `tests/openai-speech-client.test.ts`, `tests/speech-registry.test.ts`, 93/93 тестов GREEN.

## 2026-10-22 - Lean Rust ASR vs Python Footprint
- Context: Развертывание локального Sber GigaAM v3 на Mac M4 16GB.
- Symptom: PyTorch/Python стек отъедает от 1.5 до 2.5 ГБ RAM, что вплотную приближает систему к лимиту памяти при параллельной работе IDE, Chrome и Whisper.
- Cause: Большие оверхеды рантайма Python и CUDA/MPS runtime.
- Use next time: Использовать нативные Rust-бинарники (`gigastt`) с ONNX Runtime и CoreML для Apple Silicon. Вес модели INT8 — 225 МБ, потребление RAM — всего 350 МБ, старт за 2 секунды.
- Evidence: PM2 сервис `gigaam-asr` на порту 9876, `curl http://127.0.0.1:9876/v1/models`.

## 2026-10-22 - Client VAD Pitfall & Ambient Room Capture
- Context: Захват звука видеоконференции (Zoom/Meet) и голосов из внешних динамиков в веб-приложении.
- Symptom: Речь участников Zoom полностью игнорировалась браузером, ни один сегмент не отправлялся в ASR.
- Cause: 1) Дефолтный `getUserMedia` включает Chrome AEC (эхоподавление), который агрессивно вырезает звук из динамиков; 2) `AudioContext` стартовал `suspended`, обнуляя RMS; 3) Клиентский VAD-гейт молча отбрасывал сегменты без логирования.
- Use next time: Для амбиентного захвата комнаты отключать `echoCancellation` и `noiseSuppression`; непрерывно трекать пиковый RMS с порогом `0.005`; вызывать `audioContext.resume()`; обязательно писать диагностический лог о каждом обработанном/пропущенном сегменте.
- Evidence: `src/speech/stream-recorder.ts`, `src/speech/whisper-speech-adapter.ts`, 93/93 тестов GREEN.

## 2026-10-22 - Industrial VAD, EOU Debounce & Left-Context Sliding Window
- Context: Нарезка речи при спонтанном диалоге и длинных монологах в реальном времени.
- Symptom: Жесткий таймер (4.5 с) без пауз резал слова посередине слога, а статичный VAD отбрасывал тихую речь. Пользователь не понимал, слышит ли микрофон звук.
- Cause: Отсутствие End-of-Utterance (EOU) детектирования, отсутствие левого контекста при срезке непрерывной речи и отсутствие живого VU-метра.
- Use next time:
  1) Использовать адаптивный VAD на базе AssemblyAI с экспоненциальным сглаживанием шума (EMA) и hangover-фреймами (250-300 мс).
  2) Финализировать реплику по естественной паузе речи (debounce 850 мс), сохраняя преролл 500 мс.
  3) При непрерывном монологе ставить потолок (7.0 с), но передавать в следующий чанк 1.5 с левого контекста (паттерн FluidAudio `SlidingWindowAsrManager`).
  4) Всегда оснащать кнопку микрофона реактивным VU-метром (масштаб/свечение от RMS в реальном времени) и понятными статусами («слышу речь…», «распознаю…», «нейрокоррекция…»).
- Evidence: `src/speech/vad/energy-vad.ts`, `src/speech/stream-recorder.ts`, `src/speech/whisper-speech-adapter.ts`, `src/components/salon/VoiceIndicator.tsx`, 105/105 тестов GREEN.

- Symptom: Иллюзия необходимости внешних виртуальных аудио-драйверов (BlackHole) или системных демонов на Swift при использовании наушников.

## 2026-10-22 - Anti-Amputation LLM Distillation, Calm UX & Canvas Purity
- Context: Автоматическая дистилляция речевых высказываний в созерцательном пространстве Салона.
- Symptom: 1) Кнопка микрофона постоянно дергалась, меняла размеры и текст («слышу речь…», «распознаю…», «нейрокоррекция…»). 2) В круг летели бессмысленные обрывки и одиночные глаголы («поиграй», «работает», «туш»). 3) Костер перечеркивался пунктирными линиями.
- Cause: 1) Чрезмерное отображение внутренних технических фаз конвейера в UI вместо созерцательного покоя. 2) Малые LLM (Qwen 1.5B) при промпте «извлеки чувство» ампутируют 90% предложения до 1 слова, а 7-секундный таймер рубил монолог посередине. 3) Временные связи рисовались в Canvas вместо скрытого сохранения в localStorage.
- Use next time:
  1) Кнопка голосового ввода в медитативном интерфейсе должна быть статичной: спокойное «слушаю» с мягким дыханием точки громкости.
  2) Внедрять анти-ампутационный гейт: если LLM возвращает $\le 1$ слово при полноценном высказывании ($\ge 2$ слов), всегда использовать исправленный полный текст (`repaired_text`). Потолок монолога расширять до 12 с.
  3) Граф связей между говорящими должен жить как топологические данные в хранилище, не засоряя сакральное пламя костра визуальными линиями.
- Evidence: `src/domain/phrase-distiller.ts`, `src/components/salon/VoiceIndicator.tsx`, `src/canvas/hearth-words.ts`, 111/111 тестов GREEN.

## 2026-10-22 - Speaker Turn Memory Buffer & IT Lexicon Normalization
- Context: Распознавание спонтанной речи на созвонах и предотвращение фрагментации реплик спикера.
- Symptom: 1) Фразы одного спикера разрезались на куски (например, «была на бэтенде для» + «большие группы контактов»). 2) Появлялись висячие предлоги на конце фраз («для», «как»). 3) Опечатки в IT-терминах («бэтенд»). 4) Бытовой зум-шум («ты слышишь?») попадал на холст.
- Cause: 1) Чанки ASR обрабатывались изолированно (stateless per-chunk flush) без накопления реплики одного спикера. 2) Баг в `isAmputationOrLeak` расценивал `phrase: ""` как утечку и насильно подставлял сырой мусор в костёр. 3) JavaScript RegExp `\b` не работает как word boundary для кириллицы.
- Use next time:
  1) Использовать `SpeakerTurnBuffer` с дебаунсом 2.2 с (и 3.5 с при висячих союзах/предлогах): накапливать чанки одного спикера в цельную мысль до смены спикера или наступления тишины.
  2) Передавать скользящее окно истории реплик (`recentContext`) в системный промпт LLM для контекстной осведомленности.
  3) Для кириллических границ слов использовать паттерн `(^|[\s.,;:!?"'()])слово([а-яё]*)(?=[\s.,;:!?"'()]|$)` вместо `\b`.
  4) Уважать пустой возврат LLM (`phrase: ""`) при фильтрации шума и обрубков.
- Evidence: `src/domain/speaker-turn-buffer.ts`, `src/domain/phrase-distiller.ts`, `src/hooks/useSalonSpeech.ts`, 119/119 тестов GREEN.

## 2026-10-22 - Radiance Cascade Ground Light Diffusion & Vibrant Stone Highlights
- Context: Реалистичное рассеивание света костра по поляне под парящие слова и сочные блики на камнях очага.
- Symptom: 1) Световой бассейн на земле выглядел как искусственный коричневатый овал с жесткими верхними и нижними границами. 2) Свет не доходил до парящих слов и участников. 3) Блики на камнях были блеклыми и статичными.
- Cause: 1) В Canvas 2D вызов `ctx.createRadialGradient(cx, cy, 0, cx, cy, rx)` в сочетании с `ctx.ellipse` обрезал круглый градиент по высоте на $ry / rx \approx 0.36$, где непрозрачность еще составляла $> 0.20$. 2) Использование одиночного градиента малого радиуса без учета атмосферного рассеивания (Radiance Cascade). 3) Обычный `source-over` блендинг для камней без спекулярного рефлекса и мерцания пламени.
- Use next time:
  1) В Canvas 2D для идеального изометрического светового овала без видимых срезов масштабировать контекст через `ctx.translate(cx, cy); ctx.scale(1.0, ry / rx)` и рисовать круглый градиент до `r` — на границе альфа гарантированно равна 0.0 по всем осям.
  2) Использовать 3-слойный каскад света (Hearth Core, Meadow Mid-Glow, Distant Ambient Dissipation с $R \ge 800..1000$px), мягко освещающий землю под словами.

  4) Для живых бликов на камнях использовать `lighter` блендинг, направленный градиент к очагу, индивидуальный фликкер пламени и тонкую спекулярную дугу по верхнему гребню.
